# 公式卡检查

用于 OCR/PDF 转卡后含 `[E##...]` 的卡片。目标不是自动“猜对公式”，而是在交付前把可疑公式找出来，避免把 OCR 错误写进墨墨。

## 本案例暴露的问题

| 问题 | 例子 | 处理 |
|---|---|---|
| 公式被拆成多个片段 | `[E##R(0)=]`、`[E##H(s)+]`、`[E##W =]` | 合并/重写成一个公式，或改成正文说明；不要留孤立运算符 |
| 行尾截断 | `[E##y(n) = x(n) *]` | 补全 `h(n)` 或标注“原文截断，待核对” |
| OCR 变量误读 | `\{f(y)\}`、`e^{N f \omega \tau}` | 回到原图/原 PDF 核对；不凭常见替换猜 |
| 公式定界符残留 | 正文还有 `$...$` | 所有公式统一转成 `[E##...]`，不要混用 |
| 公式内混入 Markji 标签 | `[E##... [T#...] ...]` | 公式必须是纯 LaTeX；标签放公式外 |
| 修复只作用于备注 | 正文 items 里仍有旧错误 | 标题、items、要点、易错、答案、备注全部走同一修复函数 |
| 标题被公式/标记吃掉 | 标题为空或变成“教材依据” | 先 token 化公式，再解析标题和段落 |

> 注：`z^*` 这类共轭星号是合法结尾；检查器不会把它误报为“悬挂乘号”。

## 整行公式规则

如果这一行本身就是一条公式，**整行只放一个 `[E##...]`**：

```text
[E## y(n)=x(n)*h(n) ]
```

不要拆成：

```text
[E##y(n)=] [E##x(n)*h(n)]
```

边界：

- 纯公式行：整行包裹，不再拆成多个公式片段；
- 行内公式：保留在句子中，不能把整句中文包进 `[E##...]`；
- 公式 + 中文说明：公式单独包裹，中文放在公式外；
- 公式 + 编号/标点：编号和标点放公式外，不要塞进 LaTeX。

## 整行包裹 + 换行（v1.2）

当一条答案里有中文和公式、又需要整行控制换行时，使用：

```text
python -B scripts/wrap_formula_lines.py cards.json --output cards_wrapped.json
```

输出写进 `content_wrapped`，不覆盖原 `content`。

规则：

- 只处理答案区中以 `①`–`⑩` 开头的行；
- 行首编号留在公式外，整条答案包成 `[E##[F#n#...]]`；
- 中文转成 `\text{}`，按 8 字/标点切块，块间插入 `\allowbreak`；
- 公式按顶层逗号拆开，不切断括号、上下标和 `\{ \}`；
- `[T#B#...]` 转成红色加粗文本；其他文本标签转普通 `\text{}`；
- 图片、选择题、卡片引用等标签不在本脚本处理范围，遇到会报错，需先拆到公式外；
- 生成后必须在真实客户端抽查：`[E##[F#n#...]]` 的嵌套、`\allowbreak` 断点和移动端行宽都要验证。

这是“整行包裹”的可重复路径；不要为每张卡临时改脚本。

## 生成前

1. 先把所有公式替换成占位符（如 `[[F0]]`），再处理分段、标题、编号和 Markji 标签；最后回填公式。
2. `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 统一转成 `[E##...]`。
3.  OCR 公式的字符修复只做**有证据的定向修复**，不全局把 `v` 换 `τ`、`w` 换 `ω`。
4. 公式不参与自然语言分段、标题截断、编号拆分；不要在 `+ - * / =` 处断行。

## 交付前

```text
python -B scripts/check_formulas.py cards.json
```

退出码 1 表示有可疑公式。检查项：

- `$` 残留；
- 未闭合 `[E##`；
- 空公式；
- 公式尾悬挂运算符；
- 花括号不平衡；
- `\sqrt\lbrack`、离散信号里的 `f(y)`、`N f` 等已知 OCR 可疑形态。

它只报告，不自动改公式。通过脚本不等于公式渲染正确；公式卡仍要在 Markji 客户端抽查，尤其是分式、上下标、积分上下限和希腊字母。

## 修复优先级

```text
原图/原 PDF 核对
→ 公式槽位重新拼接
→ 必要时重写整句
→ 再跑检查器
→ 客户端看渲染
```

没有原图证据时，宁可标注“待核对”，不要静默补一个看起来合理的公式。
