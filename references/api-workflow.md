# 专业版：官方 OpenAPI 工作流

先完成 SKILL.md 的会员确认与最新文档检查。本文件是工作流程，不是固化的接口规范。

## 鉴权与权限

只用官网当前公布的生产 HTTPS 服务。2026-10-11 核对的基础地址为 `https://open.maimemo.com/open/api/v1`，鉴权为 `Authorization: Bearer <MAIMEMO_TOKEN>`；每次使用重新核对。不要把凭证发送给 tutuji、GitHub、表格渲染器或第三方 TTS。

优先通过安全凭证输入或进程环境变量读取 `MAIMEMO_TOKEN`。不要求用户把密钥贴进公开聊天；用户已提供的密钥只用于其授权操作，不再次输出或持久化。不能复用其他技能的短期 Web token 代替官方凭证。

**只能配置用户自己的 key**：他人提供的、共享的、来源不明或疑似他人的 key，不得写入本机环境变量；来源存疑时先停下确认。写入前必须用问题框说明「接错会操作到别人的账户」，并让用户确认是自己的 key。

凭证读取顺序：用户级环境变量 `MAIMEMO_TOKEN` → 用户本次提供的 key。环境变量存在时**不要重复索要 key**。首次拿到 key 且环境变量尚未设置时，用问题框问一次是否写入用户环境变量；同意后用 `setx MAIMEMO_TOKEN "<key>"` 设置（仅用户级、不回显；只影响新启动的进程，本次会话继续用当前 key），此后各会话直接读取。用户级环境变量是唯一允许的持久化位置，且必须经这次明确同意；任何情况下都不得写进技能文件、状态文件、日志或 Git。

用当前文档中的最小只读请求验证鉴权；连接成功不代表所有写权限已具备。会员状态以用户原话为准；用户已提供可用 API 凭证时视为已开通专业版，不再重复询问，也不要只凭一次只读请求成功推断。没有密钥、权限被拒、鉴权过期或文档不可访问，停止写入并报告。

## 目标与样卡

1. 读取真实牌组、章节及必要的卡片，按文档分页。用户给序号时解析真实顺序和 ID，不能把序号直接当 ID。
2. 新建目标牌组若无官方接口，请学习者自行创建；不要猜创建路由或换成逆向 Web API。章节创建等额外动作须在用户请求范围内。
3. 改卡前读最新完整正文、语法版本和更新时间；保存不含凭证的本地基线。模板引用读取真实源码和媒体，不能只根据截图猜标签。
4. 制作本地预览/变更清单，记录源材料稳定键、目标牌组/章节/卡片 ID、旧内容摘要、拟写入的完整内容、媒体映射和处理状态。只针对用户授权目标。
5. 已明确请求准确目标与内容可执行该修改；目标或批量内容尚未确认时，展示少量样卡、预计数量与覆盖范围并等确认。不把“制作技能”或“测试接入”当成写卡授权。

## 创建、更新与媒体

发送前从实时官方定义核对方法、路径、路径/正文 ID 字段、required 字段、位置 order、语法版本和 MIME。文档中的创建和更新接口可能使用不同 ID 字段名，不能套用一份通用 payload。

### 已实测的创建请求体陷阱（2026-10-14）

当 URL 使用官方 GET 返回的 `mkjd_…` / `mkjch_…` ID 时，创建卡片采用路径寻址：

```text
POST /open/api/v1/markji/decks/{deck}/chapters/{chapter}/cards
```

已成功创建并 GET 回读四张真实选择题（包括题面图片与解析图片）的最小请求体为：

```json
{"card":{"content":"完整 Markji 语法文本","grammar_version":3}}
```

不要把 `deck` / `chapter` 再放入创建请求体。当天官方 `api_bundle.yaml` 仍把这两个字段列为 body required，但实测重复传入官方长 ID 会返回 HTTP 400 / `common_invalid_param`：`deck not a valid ObjectId`、`chapter not a valid ObjectId`；仅移除可选 `order` 并不能解决。遇到同一症状，先核对 URL 的真实目标和远端未新增，再在用户已授权的真实样卡上做一次“仅 card”的最小修复，并回读逐字符核对正文、版本与章节归属。此经验只适用于上述创建接口，不推断更新、移动或媒体接口也应删除其正文 ID 字段；`order` 的插入行为另行验证。

这类 ObjectId 错误是参数/寻址诊断依据，不足以断言会员未开通、账号无写权限或整个官方 API 不可用；不要猜测内部 ObjectId 或自动改走 Web API。非法 `grammar_version=999` 返回语法错误只能说明到达相应校验，不能证明合法卡片必定保存，也不应未经证据承诺探针绝对无副作用。优先使用已授权的真实样卡并核查远端数量；写响应不确定先查询，禁止盲目重发。

`card.content` 是完整 Markji 语法字符串。媒体卡按当前 tutuji 指南配套使用整数 `card.grammar_version: 3`，与 content 同级；每次核对最新版本要求。旧卡升级语法版本须用完整正文试验并回读，不仅修改媒体片段。

图片、音频和遮罩先上传，再读取返回的完整、大小写敏感 `file.id`，回填已验证语法。不能截短、解密、替换成长短 ID 的猜测值。卡片引用用真实 `root_id`，不是路径中的 `card.id`；不要混用官方 ID、Web 内部 ID 和引用 ID。

遮罩需要时先读 tutuji 最新第 6.3 节：最终原图尺寸固定，矩形坐标按原图归一化，`.msk1` 是描述区域的 JSON，不是预览 PNG。图片和遮罩分别上传并保留映射，不生成未经验证的形状类型。

## 小批试验与可恢复执行

- 先试写一张代表性卡，回读成功后再扩展。每一种新结构（选择题、公式、媒体、遮罩等）都要样卡验证；渲染需要在真实客户端检查，接口成功不能替代。
- 修改前核对基线仍未变化；存在外部编辑则停止冲突项，不覆盖新内容。更新既有卡保留身份，不删除重建；不承诺未经核对的学习进度不变。
- 防重复按源材料稳定键和记录的真实目标 ID 执行，不依赖隐藏标签。重跑先读取远端，不能只按标题匹配；歧义留给用户确认。
- 每次写入后 GET 回读，逐字符比对正文、媒体 ID、版本与目标章节，核对新增数量和顺序。保存返回的新 ID 和核验状态，不保存凭证。
- 写请求超时或丢失响应时，先只读核查状态。创建是否已成功无法确定时停止，不能盲目重发产生重复。
- 按实时官方频控限速；遇 429 尊重 Retry-After，超过限额停止或在用户授权的后续机制中继续，不靠持续重试。
- 修复一张错误卡后再次回读并预览；同一症状一次最小修复仍失败，停止批量并按 tutuji 排障，不循环猜参数。

交付报告区分“已上传”“回读一致”“客户端渲染已验证/待验证”，列出成功、失败和跳过数量，不将部分成功说成全部完成。
