# 公式自定义颜色

`[E##...]` 内部由 KaTeX 渲染，颜色不走 Markji 的 `[T#...]`，而是在公式里写 `\textcolor`。

## 基本写法

```text
[E##\textcolor{#d16056}{E_k=\frac{1}{2}mv^2}]
```

中文混排：

```text
[E##\text{普通 }x^2\text{ 与 }\textcolor{#d16056}{x^2}\text{ 对比}]
```

红色加粗中文：

```text
[E##\text{\textcolor{#d16056}{\textbf{关键术语}}}]
```

## 颜色范围

只使用 Memo 设计系统已有的语义色，不临时新增彩虹色：

| 用途 | 颜色 |
|---|---|
| 关键结论 / 主强调 | `#36B59D` |
| 易错 / 术语强调 | `#D16056` |
| 模糊 / 提醒 | `#EB9E27` |
| 警告 | `#DC663E` |
| 中性辅助 | `#8E8E8E` |

规则：

- 一条公式最多一个强调色；
- 不把整条公式染成一种颜色；
- 不为了好看给每个变量上色；
- 同一张卡不要混用多套强调色；
- 颜色是语义，不是装饰：关键项、易错项、正负号才上色。

## 与 Markji 文字色的区别

```text
[T#!d16056#文字]        只影响卡片文字，管不到公式内部
\[E##\textcolor{#d16056}{...}]   只影响公式内部，不影响公式外的文字
```

两套系统不要互相替代。

## 兼容性

`\textcolor` 是 KaTeX 能力，不是 Markji 文档承诺的能力。当前只在部分客户端验证过。

- 必须在目标客户端实际查看；
- iOS / Android / 网页三端分别抽一张；
- 如果某端不识别，降级为纯公式或普通 `[T#...]` 文字，不静默保留可能不渲染的写法；
- 命名色（`red`）和六位十六进制都可以，但优先用本技能的语义色值；
- 公式里的 `#` 只在 `\textcolor{#...}` 中使用，不要和 Markji 标签混在一起。

## 交付检查

```text
python -B scripts/check_formulas.py cards.json
```

检查器会检查 `\textcolor` 的十六进制格式和花括号；它不能证明客户端一定渲染，公式颜色仍要人工抽查。
