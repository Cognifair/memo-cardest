# 牌组合并（Merge Decks）

合并两个 Markji 牌组到用户指定的目标牌组。**只复制和核验；不删除卡片、章节或牌组。**

## 已确认的边界

- 新牌组由用户在客户端创建；官方 API 不能新建牌组。
- 目标牌组必须已经存在；API 只能 GET 验证。
- 删除源牌组由用户手动完成；Agent 不调用删除接口，也不建 `DELETE` 章。
- 图片/音频按原样复制 `content`，但必须先做一张样本验收。
- 学习进度不会迁移，开始前就要说明。
- 纯 TXT 不能自动修链接；TXT 只能是 C 路线：TXT 导入 + API 回读/修复。
- 外部卡不自动修改；只检测并报告入链。

## 先只读盘点

```text
python -B scripts/merge_plan.py \
  --source <源牌组 ID 或准确名字> \
  --source <另一个源牌组> \
  --target <已存在的目标牌组 ID 或准确名字> \
  --route api \
  --output merge-plan.json \
  --preview merge-preview.md
```

选项：

- `--route api`：API 直连复制；
- `--route c`：TXT 导入后 API 修复；
- `--scan-inbound`：额外扫描其他牌组，找出“外部卡 → 源卡”的入链；只读，可能较慢；
- `--overwrite`：允许覆盖已有 plan/preview。

脚本只做 GET，不写账户。

输出：

```text
merge-plan.json     完整计划（含卡片正文、哈希、链接分类）
merge-preview.md    给用户看的摘要
```

## 目标牌组

用户先在客户端创建，然后输入准确名字。

如果同名多个：

> 请提供目标牌组 ID；仅按名字无法确定。

验证：

```text
API GET /decks
→ 精确匹配名字或 ID
→ 不存在就停下，要求用户先创建
```

不要把“新牌组”当成 API 可创建对象。

## 路线

### API 直连复制

```text
读源牌组
→ 建目标章节
→ 写目标卡片
→ 回读新 root_id
→ 重写内部链接
→ 验收
```

新卡 `root_id` 从创建响应/回读直接获得，映射最可靠。

### C：TXT 导入 + API 修复

```text
生成 TXT
→ 用户手动导入目标牌组
→ API 回读目标牌组
→ 用内容哈希或临时标记匹配
→ 重写内部链接
→ 验收
```

C 仍然需要 `MAIMEMO_TOKEN` 和 API 写权限。  
没有 API 时不能承诺链接可修复。

## 链接分类

| 类型 | 方向 | 处理 |
|---|---|---|
| A | 被复制卡 → 被复制卡 | 旧 `root_id` → 新 `root_id` |
| B | 被复制卡 → 源牌组外的卡 | 保持原样，不重写 |
| C | 源牌组外的卡 → 被复制卡 | 不自动改外部卡；报告，删源前处理 |
| D | 被复制卡 → 未复制的源卡 | 没有目标；警告或补复制 |

外部卡自己的 ID 不变；要检查的是它指向源卡的**入链**。

## 重复卡与章节冲突

`merge_plan.py` 会先统计：

- 内容哈希相同的重复卡；
- 同名源章节；
- 源章节与目标现有章节重名；
- 空章节。

只有发现冲突才问用户：

```text
发现：
- 同名章节：N 组
- 内容重复卡：M 张
- 空章节：K 个

请选择：
A. 合并同名章节，跳过重复卡
B. 保留同名章节，重复卡都保留
C. 自定义
```

不要自动去重，也不要自动改名。

## 检查点

### CP0：目标与路线

用户确认：

- 目标牌组名/ID；
- API 直连还是 C；
- 是否接受学习进度丢失。

### CP1：合并预览

用户确认：

- 章节映射；
- 重复卡处理；
- 同名章节处理；
- 媒体样本；
- 链接风险。

### CP2：删源前

用户必须在客户端实际检查：

- 图片/音频；
- 公式/表格；
- 链接跳转；
- 章节顺序；
- 卡片数量。

确认后才能手动删除源牌组。

## 失败处理

| 失败 | 处理 |
|---|---|
| 目标牌组不存在 | 停止，要求用户先创建 |
| 目标同名多个 | 要求 deck id |
| 无 Token/401 | 停止，不猜权限 |
| 媒体样本失败 | 停止批量，改路线 |
| 重复内容无法映射 | 暂停，询问临时标记 |
| 部分写卡失败 | 保留源，回读确认，不删源 |
| 外部入链未处理 | 删源前警告，不自动删 |

## 执行复制（API 直连）

先确认计划，再执行；不传 `--apply --allow-upload` 时是 dry-run：

```text
python -B scripts/merge_apply.py \
  --plan merge-plan.json \
  --apply --allow-upload
```

含图片/音频时先复制一张样本：

```text
python -B scripts/merge_apply.py \
  --plan merge-plan.json \
  --sample --apply --allow-upload
```

重复内容需显式选择：

```text
--skip-duplicates    每组内容只保留第一张
（不加则计划含重复卡时拒绝执行）
```

如果已经复制过一张样本，再跑全量时加：

```text
--skip-existing      跳过目标牌组中已存在的相同正文
```

避免样本卡被重复创建。

`merge_apply.py` 只创建章节和卡片，不删除、不移卡、不改名。链接重写暂未接入；计划里出现内部链接时会拒绝执行，避免把断链当成功。

## 当前实现

- `scripts/merge_plan.py`：只读盘点 + plan/preview；
- `scripts/merge_apply.py`：API 直连复制，支持 dry-run、样本、跳过重复；不删除；
- `scripts/test_merge_plan.py` / `test_merge_apply.py`：离线测试；
- C 路线的 TXT 匹配和链接重写仍在后续阶段；计划里出现内部链接时当前不执行。

## 禁止

- 不调用任何删除接口；
- 不建 `DELETE` 章；
- 不自动修改外部卡；
- 不把纯 TXT 说成能修链接；
- 不在没有目标牌组 ID 的情况下写卡；
- 不在用户验收前提示“可以删源”。
