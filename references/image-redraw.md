# 图像重绘审查（G1.4.1）

位置在 G1.4 源文件预检之后、G1.5 表格审查之前。它处理**表格之外**的视觉内容，避免模型把扫描公式、化学结构、流程图只当成 OCR 文本。

## 什么算需要重绘的图

- 图片公式、数学推导截图、几何图、坐标图；
- 化学结构式、反应式；
- 流程图、框图、系统结构图；
- 其他需要保留结构、不能只用 OCR 文字替代的扫描图。

不算：

- 普通照片、装饰图、仅用于排版的背景；
- 表格（走 G1.5）；
- 纯文字扫描页（G1.4 的 OCR 路线已经处理）。

## 决策

```text
材料里有需要保留结构的图？
  ├─ 有 → 调用 memo-canvas
  │        └─ 由它问：原样 / 简单高清化 / 精美重绘
  │        └─ 需要重绘时，它按图形类型重建并核验
  ├─ 没有 → figures: none，继续 G1.5
  └─ 用户明确不处理 → figures: user-skip，保留原图并说明，不假装已重绘
```

## 与表格、OCR 的关系

- **G1.4.1 和 G1.5 同时命中**：只调用一次 `memo-canvas`，把表格和图形一起交给它；不要连续调用两次、不要让用户回答两套重复问题。
- **图片版材料**：先走 G1.4 OCR；OCR 只拿到文字，不代表图形已经重绘。OCR 后的公式/结构/流程图仍要按 G1.4.1 交给 `memo-canvas`。
- **文字层里有嵌入图**：不需要 OCR，但 G1.4.1 仍要检查这些图。
- **表格**：由 G1.5 触发；`memo-canvas` 本身同时支持表格和图形，所以可以一次处理。

## 主技能不做什么

- 不在 cardest 里用 PIL/HTML 临时重画公式、分子或流程图；
- 不把 OCR 出的 `α/β`、上下标、化学键当成已还原；
- 不覆盖原图；
- 不因为“图很简单”跳过用户的图片处理模式选择；
- 不把 `memo-canvas` 的本地预览说成 Markji 客户端已验收。

## 留痕

```text
figures: found(N) → memo-canvas invoked
figures: none
figures: user-skip
visual: tables+figures → single memo-canvas call
```

G4 验收时检查内容（符号/键/箭头/数值）和视觉（字号/线宽/裁切）两层，不能只检查“图能显示”。
